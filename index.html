From dataset to model

ML development with coding agents

Enrique Munguía · 30/10/2026

→ next   ← back   N notes   F fullscreen   ? help

Opening. This is a story about one small computer-vision project and the coding agent that sat next to me for all of it. The task: find overlays on product photos. The point is not the model. The point is where the agent carried the work, where it had to stop and wait for me, and what that tells you about putting agents into your own ML loop.

Everything in the deck comes from a real repository. The numbers are real, including the bad ones.

The task

Find the overlays on a product image

presencetypebox
promo_badgeburst, pill, circle
floating_textcomposited words
watermark_logooften low opacity
banner_ribbonedges and corners
graphic_stickerstars, hearts, checks

The problem. E-commerce catalogs are full of product photos where someone pasted a promotional element on top of the picture. We want a model that says whether an overlay is present, what kind it is, and where it is.

Five classes. Promo badge, floating text, watermark or logo, banner ribbon, graphic sticker. This ontology is the first human decision in the whole project and it was written down in PLAN.md before any code existed.

Build: each keypress adds one overlay with its labeled box, and lights up the matching class on the right.

The task

Printed text is not an overlay.

Human

Decide what the model must ignore: packaging text, product logos, book covers, screens, scene signs.

Human

Only digitally composited elements count. Write that sentence down before the first line of code.

Agent

Carries the rule everywhere: generator, labeling tool, evaluator, and every report it writes.

The hard part. A label on a shampoo bottle, a book title, a phone screen: all of these are text on an image and none of them is an overlay. The model has to learn the difference between printed and composited.

These negative kinds became an explicit list in the labeling tool. The agent never had to guess what a negative was, because I had told it. When I asked for something underspecified later, it stopped and asked.

Overview

One loop, five stations.

Agent

Builds the tooling, runs the experiments, records everything, writes the report.

Human

Defines the problem, judges the data, labels, sets thresholds, decides when to stop.

Automate

The part of each station that can run unattended once the rules are written down.

The map for the talk. Explore the data, label it, pick and train a model, evaluate it, improve it, and go around again. Every station in this deck gets the same three-way split: what the agent did, what I had to do, and what can run on its own.

The three colors stay fixed for the rest of the deck: blue is the agent, yellow is the human, green is automation.

Before the loop

The agent forgets. The files remember.

PLAN.md

# Mission Detect digitally added overlays on product images: presence, type, box. # Ontology promo_badge · floating_text watermark_logo · banner_ribbon graphic_sticker Printed text and logos are negatives. # Milestones 1 Synthetic data → gate: contact sheet 2 Real sources → gate: source triage 3 Baseline → gate: tiny overfit 4 Real evaluation → gate: 50 reviewed # Fresh-session handoff Start here. Do not repeat the M1 review.

AGENTS.md

Read PLAN.md before changing scope. Python 3.11 and uv. Run pytest and ruff. Visually inspect the contact sheet. Training must pass the mandatory tiny overfit test before scaling. Keep seeds, provenance, configuration and asset hashes in metadata. Keep product groups within one split. Never treat uncertain sources as clean. Do not fabricate review decisions or real evaluation annotations. Keep modules simple, typed, and readable.
Human

Hard rules go in writing. Short, imperative, and mostly do not.

Human

Each milestone ends at a gate where a person looks before the agent continues.

Agent

Reads both files at the start of every session. Writes the handoff at the end of it.

Two files carried the project. PLAN.md holds the mission, the ontology, the milestones, and a section called "fresh-session handoff" that the agent rewrites at the end of every session. AGENTS.md is about twenty lines of rules.

Why it matters. Every rule the agent later enforced in code (the overfit gate, the leakage-safe splits, the refusal to invent labels) traces back to one of these lines. The agent does not remember yesterday. The files do.

Found Amazon Berkeley Objects. Wrote the downloader and verified all the files.

Automate

Review sheets for every batch. Same seed, same 1,000 images, every run.

Human

Look at the sheets. Decide whether this data is the problem you are solving.

Exploration. There is no public overlay-detection dataset. The agent proposed Amazon Berkeley Objects, a CC BY 4.0 catalog of product photos, and wrote the acquisition code: deterministic selection by SHA-256 ranking with a seed, byte limits, timeouts, atomic writes, per-image failure records, and a manifest so a rerun verifies hashes and skips what it already has.

The agent looked too. It opened the first review sheet and noticed that real listings already contain composited callouts next to printed branding. It flagged that source review was necessary and did not quietly mark anything clean.

Human. I still had to look at the sheets myself and decide that this catalog represents the problem. Nobody else can make that call.

Data exploration

No labels? Make them.

Gate 1 · 100 images, 120 boxes, 23 negatives · the agent waited
Agent

Built a generator for all five classes: shapes, fonts, placement, opacity, occlusion, clipped boxes. 108 tests.

Automate

Every image is replayable from its record. A single box with bad coordinates, like zero size or a box outside the image, fails validation for the whole dataset.

Human

Look at the contact sheet. Bad synthetic data makes the experiment look successful while teaching the wrong problem.

Synthetic first. Milestone 1 was a generator that composites badges, text, watermarks, ribbons and stickers onto clean product images and writes COCO boxes measured from the actual visible pixels after rotation, clipping and occlusion.

Reproducibility came for free because AGENTS.md asked for it once: per-sample seeds derived from the global seed, source id and index; font and asset hashes; renderer version; a replay command that regenerates any image and checks the pixel checksum.

The gate. The plan said: stop after milestone 1, show a contact sheet, wait. I opened it in Chrome, said "looks good", and the agent recorded that sentence and the date in the milestone report. That quote about bad synthetic data is in PLAN.md and it is the reason the gate exists.

Training data labeling

The agent built the labeling tool.

The real thing. The agent launched it and drove Chrome itself: drag, reverse drag, resize, undo, zoom, pan, reload, save. 168 tests.
Agent

Standard-library server, SVG canvas, keyboard shortcuts, drafts, atomic saves with backups. No build step.

Automate

Reserving an image reserves its whole product group, so nothing lands in both training and evaluation.

Human

Manually labels the images by drawing boxes.

Labeling. I asked for a local labeling tool with two workflows: source triage (clean / overlay / uncertain, keys 1 2 3) and real evaluation annotation (draw boxes, pick a class, confirm). One session. The agent wrote a plan document first, then the server and page, then it opened Chrome and exercised every interaction with real mouse and keyboard events, and recorded the evidence.

Leakage safety is built into the tool. Images of the same product, or sharing a source hash, form a connected group. Labeling one reserves the whole group for one purpose. The training manifests you supply are checked, so an image that was already trained on cannot become an evaluation example.

Human. The tool is great. I still had to draw every box.

The best thing the agent did was nothing. The export tool refused to produce a real evaluation set with zero reviewed images, and the agent refused to fill the gap. AGENTS.md says "do not fabricate", and it held through four milestones and a dozen sessions.

Then I labeled. 329 source decisions and 92 evaluation annotations in one evening, with the tool the agent had built that afternoon.

And the agent read the result. It queried the running tool's state endpoint, computed class coverage, and wrote a handoff note telling me which classes had no examples yet and which product types were overrepresented. That is exploration again, on my labels.

Automation glimpse. The project already has a template for model-generated reference labels, kept in a separate cohort, never mixed with human ground truth.

Architecture and weights

Start boring.

Human

Pretrained detector first. Do not begin with JEPA or custom representation learning. Written in the plan.

Agent

COCO to YOLO conversion, grouped 80/10/10 splits, training script, stable prediction JSON.

Automate

Blocks real eval images from being converted to training data. Images from the same product stay together in one split.

Architecture is a human decision, and the boring one wins. The plan explicitly says to establish a conventional baseline before any self-supervised or custom representation work. The agent would happily have built a JEPA pipeline. It is much better at building what you ask for than at knowing what you should ask for.

What the agent did well: the unglamorous plumbing. Converting COCO to YOLO format, grouping images into connected components so that variants of one product never straddle train and test, and refusing at the tool level to convert real evaluation data into training data.

The tiny overfit test. Before any real training run, take 64 images, point validation at the same 64, switch off augmentation, and train until the model memorizes them. If mAP, precision and recall do not all clear 0.90, the pipeline is broken somewhere: labels, conversion, class ids, image size.

What is unusual here is that the agent made the gate structural. The baseline config points at the gate file. If the gate is missing, failed, or its hashes do not match the current checkpoint and dataset, training refuses to start. A rule in AGENTS.md became a check in code.

The baseline itself is a short 20-epoch YOLOv8n run on illustrated fixtures. Validation mAP@0.5 was 0.55 with recall 0.43. The agent's own report calls it weak. That honesty matters later.

A detour worth taking. Before investing in training data, ask a hosted vision-language model to do the task zero-shot on a small, deliberately enriched real sample, to see whether training is needed at all. The agent built the whole pilot: sampling with provenance, cached requests so a rerun costs nothing, an interactive grading report, and separate metrics for human versus model references.

The result shaped the plan. Image-level presence was decent out of the box. Typed boxes were near zero. So the trained detector is for localization and type, and a foundation model could serve as a cheap presence pre-filter or a pre-labeler.

Human judgment again. I graded the sample and reported that the OCR transcriptions were poor. The agent recorded that as a material limitation and listed the controlled follow-up it would take to separate transcription errors from classification errors. It did not run that follow-up on its own.

Agent

Read token counts from the pilot's 53 cached calls, then sent the 36 images a single yes/no question: 838 tokens, $0.000035 each.

Human

Sets the budget and decides when to escalate missed examples.

Automate

Every escalated image comes back labeled and joins the next training lap. The tail shrinks.

The tradeoff. In similar tasks, a Gemini 3 family model gave me precision and recall above 0.95. That is better than anything trained here so far. But a hosted model is a per-image bill, every time the catalog is re-scored, while your own detector is mostly a fixed cost: labels, engineering time, a training run. At tens or hundreds of millions of images the per-image line wins the argument.

Where the numbers come from. The pilot VLM rows use measured tokens: 3,265 input tokens for the full slide-12 prompt, and 838 for a yes/no presence question the agent sent to the same 36 images, at $0.042 per million input tokens with free output. Gemini rows are estimates at batch prices from the October 2026 price page: about 1,600 input tokens per image (1,120 for the image at default resolution plus the prompt) and about 1,000 output tokens including thinking. Thinking is the big unknown; measure it before quoting. The YOLOv8n line assumes roughly 500 images per second on one rented L4.

The tiered answer. Run your own detector on everything. Send only the unsure band, a few percent, to the expensive model, and the leftovers to a person. Every escalation becomes a label, so the next model needs fewer. Three percent of 100M at Pro batch prices is about $23k instead of $760k, and the hard tail still gets the 0.95 model.

The catch. A cascade cannot fix confident mistakes. On the yes/no run, every score above 0.6 was a real overlay, but three of the thirteen overlays scored under 0.05 and would never have been escalated. Tune the routing thresholds on validation and measure the whole cascade, not each tier alone.

Provenance by default. Every training run saves its config, seed, git commit and uncommitted diff, hashes of every source file, the lockfile, the initial weights, and the dataset manifest, next to the metrics and logs. New output names are required; an existing run directory is never overwritten.

Why this is an agent strength. Humans skip this because it is tedious. The agent does not get bored. One sentence in the rules file bought the whole receipt.

The honest caveat it also wrote: on Apple MPS some kernels are nondeterministic, so a recorded seed does not promise bit-identical weights.

Improvement loops

Close the loop.

next lap › hypothesis: fixtures don't look like real catalogs → change: synthesize on 294 real photos → gate: overfit again → eval: 92 hand-labeled images
Agent

Runs the inner loop: read buckets, propose a change, retrain, re-evaluate, write the report.

Human

Approves hypotheses. Owns the stop condition. Looks at every new review sheet.

Automate

Let it run a few iterations overnight inside the guardrails. Read the morning report.

The loop the agent can run. Evaluate, read the error buckets, propose a hypothesis, change data or config, pass the overfit gate, train, evaluate again. Each lap produces a run directory with full provenance and a report.

Where the human sits. Approving the hypothesis before compute is spent, looking at any new synthetic data, and deciding when the model is good enough or when to stop. These are the yellow diamonds.

The guardrails are what make unattended laps safe: the gate, the leakage checks, the rule that synthetic numbers never get reported as real, and run directories that refuse to overwrite.

Where this project stands. The 294 clean sources are reviewed, the 92 evaluation images are labeled, and the real-data lap has not been run yet. That is the next session.

An agent builds the tool once. The whole team uses it.

From my day job. This project is one person and one model. In a team, the same loop runs over and over, and the tools the agent builds along the way stop being one-offs. They get standardized, and every new project starts with them already in place.

Labeling UI and data access. The labeling tool on slide 8 was built for this project. Once a team has one, everyone labels the same way with the same negatives. An MCP server for data access means a person or an agent asks for a sample instead of writing another downloader.

The judge. A command-line LLM judge: you pass the model's inference and a grading prompt, and an LLM returns a grade and a reason. It is the grading page from slide 12 turned into a tool anyone can run.

The golden dataset. A small, frozen, human-labeled set that every model change is checked against before anything else. It is fast because it is small, and trustworthy because people labeled it and it is never used for training. The 92 labeled images in this project are the start of one.

Why agents change the math. Internal tools used to lose the priority fight. With an agent, building one costs an afternoon, so building it for the whole team pays off much sooner.

Takeaway

Three habits that made it work.

Rules

A short file of imperatives the agent reads every session. The strongest ones say what not to do.

Do not fabricate source review decisions or real evaluation annotations.

Gates

Every milestone ends where a person looks, or where a check must pass. Make the check code when you can.

Handoffs

The agent ends each session by rewriting the start of the next one: state, counts, the exact next command.

92 completed: 12 positives, 80 negatives.
Minimum met. Next: export, then evaluate.

Rules. AGENTS.md is about twenty lines. The lines that did the most work were the prohibitions: do not fabricate, do not treat uncertain as clean, do not scale before the overfit test.

Gates. Milestone one ended with a contact sheet I had to approve. Milestone three ended with a numeric gate the code enforces. Milestone four ends with fifty reviewed real images, and the exporter counts them.

Handoffs. Long projects outlive any single session. The handoff section in PLAN.md is rewritten at the end of every session with current counts and the next command to run. The next session starts there, with no memory needed.

Limitations

Where delegation breaks.

Can't define good

It will optimize whatever you wrote down. If "good enough" is not written, it does not exist.

Over-builds

Ask for a labeling page, get atomic saves, backups, file locks and a 41 KB plan. Say how small is the task.

Sees less than you

It can inspect a contact sheet. It cannot know that phone cases are overrepresented in your catalog.

Drifts over sessions

No memory between sessions. Without a handoff it rediscovers, repeats, or quietly changes scope.

Wants to please

Left alone it would have invented clean sources on day one. The rule file is what stopped it.

Compute is real

It launches a long training run as casually as a test. Make it prove the pipeline on 64 images first.

Be honest about the limits. The agent cannot tell you what good is. It over-builds unless you bound the scope. It does not see your data the way you do, which is why the contact sheets exist. It forgets between sessions, so handoffs matter. It is agreeable by default, so the prohibitions matter. And it can spend your GPU hours without noticing, so the gates and the tiny subsets matter.

None of these are reasons not to use it. They are the reasons the human column in the table is not empty.
